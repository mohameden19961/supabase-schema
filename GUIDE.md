# Guide : Supabase + GitHub (Workflow CI/CD)

Ce guide résume tout le workflow appris, de zéro jusqu'au déploiement automatisé.

## 1. Création du repo GitHub

- Repo créé sur `github.com/mohameden19961/supabase-schema`
- Visibility : Private
- Cloné en local :
```bash
gh repo clone mohameden19961/supabase-schema
cd supabase-schema
```

## 2. Installation du CLI Supabase (Ubuntu)

```bash
npm install -g supabase
# ou, alternative officielle :
curl -fsSL https://github.com/supabase/cli/releases/latest/download/supabase_linux_amd64.tar.gz | tar -xz
sudo mv supabase /usr/local/bin/
```

## 3. Initialisation du projet Supabase local

```bash
supabase init
```
Crée le dossier `supabase/` avec `config.toml` et `migrations/`.

## 4. Connexion CLI <-> compte Supabase

```bash
supabase login
```
Ouvre le navigateur pour générer un token d'accès CLI.

## 5. Création du projet Supabase (dashboard)

Sur supabase.com/dashboard/new :
- Organization : demo-deploy
- GitHub (optional) : lié au repo `supabase-schema`
- Project name : supabase-schema
- Database password : généré via "Generate a password"
- Region : Europe
- Project ref obtenu : `camkgvkpkhawevpxmxxe`

## 6. Lier le repo local au projet Supabase distant

```bash
supabase link --project-ref camkgvkpkhawevpxmxxe
```
(demande le mot de passe DB généré à l'étape 5)

## 7. Créer et appliquer une migration

```bash
supabase migration new create_todos_table
```
Édition du fichier SQL généré dans `supabase/migrations/`, exemple :
```sql
create table todos (
  id bigint generated by default as identity primary key,
  title text not null,
  is_done boolean default false,
  created_at timestamptz default now()
);

alter table todos enable row level security;

create policy "Allow all access to todos"
on todos for all
using (true)
with check (true);

insert into todos (title, is_done) values
  ('Apprendre Supabase CLI', true),
  ('Connecter GitHub à Supabase', true),
  ('Créer une migration', false),
  ('Comprendre RLS', false);
```

Application de la migration :
```bash
supabase db push
```

## 8. Versionner avec Git

```bash
git add .

```

## 9. Nettoyage d'un fichier binaire commit par erreur

Un binaire `supabase-go` (~97 MB) a été commit par erreur. Correction :
```bash
git rm supabase-go
echo "supabase-go" >> .gitignore
git add .gitignore
git commit -m "Remove accidentally committed binary"
git push
```

Purge complète de l'historique (repo encore jeune) :
```bash
sudo apt install git-filter-repo
git filter-repo --path supabase-go --invert-paths --force
git remote add origin https://github.com/mohameden19961/supabase-schema.git
git push origin main --force
```

## 10. Modifier une table existante (ALTER TABLE)

```bash

```
```sql

add column priority text default 'medium' check (priority in ('low', 'medium', 'high'));
```
```bash
supabase db push
git add . && git commit -m "Add priority column to todos" && git push
```

## 11. RLS basé sur l'authentification

```bash
supabase migration new add_auth_to_todos
```
```sql
alter table todos
add column user_id uuid references auth.users(id) default auth.uid();

drop policy "Allow all access to todos" on todos;

create policy "Users can view their own todos"
on todos for select
using (auth.uid() = user_id);

create policy "Users can insert their own todos"
on todos for insert
with check (auth.uid() = user_id);

create policy "Users can update their own todos"
on todos for update
using (auth.uid() = user_id);

create policy "Users can delete their own todos"
on todos for delete
using (auth.uid() = user_id);
```
```bash
supabase db push
git add . && git commit -m "Add user-based RLS to todos" && git push
```

## 12. CI/CD avec GitHub Actions

### a. Générer un token Supabase
Sur `supabase.com/dashboard/account/tokens` → Generate new token.

### b. Ajouter le secret sur GitHub
Repo → Settings → Secrets and variables → Actions → New repository secret
- Name : `SUPABASE_ACCESS_TOKEN`
- Secret : le token généré

### c. Créer le workflow

Fichier : `.github/workflows/deploy.yml`

```yaml
name: Deploy Supabase migrations

on:
  push:
    branches: [main]

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: supabase/setup-cli@v1
        with:
          version: latest

      - run: supabase link --project-ref camkgvkpkhawevpxmxxe
        env:
          SUPABASE_ACCESS_TOKEN: ${{ secrets.SUPABASE_ACCESS_TOKEN }}

      - run: supabase db push
        env:
          SUPABASE_ACCESS_TOKEN: ${{ secrets.SUPABASE_ACCESS_TOKEN }}
```

```bash
git add .github/workflows/deploy.yml
git commit -m "Add CI/CD workflow for Supabase migrations"
git push
```

### d. Résultat
Chaque `git push` sur `main` déclenche automatiquement `supabase db push` via GitHub Actions — plus besoin d'agir manuellement.
